# 후속 개선 과제 — 승인 근거 E3 증거를 실행 이력 보관 한도와 분리해 보존

- 상태: **기록만(미구현)**. 변경 패키지(P1–P5) 범위에 넣지 않습니다.
- 기록일: 2026-11-26
- 발견 경위: 실제 제품 개발 중(엔진 사용 프로젝트) 발견

## 1. 문제

`/product-build`의 AC 검증은 테스트 케이스별 실행 기록을 최근 12건만 보존합니다.

- 위치: `skills/product-build/scripts/pb_verify.py` — `HISTORY_KEEP = 12`, `update_history()`가 `h["records"] = h["records"][-HISTORY_KEEP:]`로 오래된 기록을 잘라 냄
- E3(실패 → 수정 → 성공) 판정은 같은 테스트의 **실패 기록**과 이후 **성공 기록**이 모두 이력에 있어야 성립합니다.
- 회귀 실행·재검증이 반복되면 성공 기록이 12건을 넘고, 승인 근거였던 실패 기록이 밀려납니다.
- 결과: 이미 검증·사용자 승인까지 끝난 AC가 다음 검증에서 E3 근거를 잃습니다. 실제 사례에서는 정상 승인된 AC의 목표를 E2로 낮춰야 했습니다(증거 수준을 낮추는 우회).

## 2. 목표

- 승인에 쓰인 E3 증거(실패 기록·성공 기록 쌍, 해당 test_sha·test_copy·tree)는 일반 실행 이력 보관 한도와 **별도로** 보존합니다.
- 일반 이력은 지금처럼 한도로 정리하되, 승인 근거로 고정된 기록은 정리 대상에서 빠집니다.
- E3 기준 자체(실패 증거 필수, 테스트 약화 감지, fault_injection·test_changed 구분)는 낮추지 않습니다.

## 3. 설계 방향(검토용 초안)

1. 배치 최종 승인 시점(`approve batch`)과 `verified` 판정 시점에, E3 판정에 쓰인 기록 쌍을 `evidence_pins`(케이스 ID → {red, green, run, tree, test_sha, test_copy, approved_at})로 고정합니다.
2. `update_history()`의 정리 대상에서 고정 기록을 제외합니다(또는 별도 저장 구역에 복사).
3. 이후 검증에서 E3 판정은 일반 이력 + 고정 기록을 함께 봅니다. 고정 이후 테스트 파일이 약화·변경되었으면 기존 규칙(`test_weakened_or_changed`)대로 무효로 처리합니다.
4. 승인이 무효화(계획 재승인으로 배치 재검증, 패키지 취소 등)되면 고정도 무효 표시만 덧붙이고 지우지 않습니다.
5. 기존 build.json과 호환: 고정 구역이 없으면 지금 동작 그대로입니다. 마이그레이션은 덧붙이기만 합니다.

## 4. 완료 기준(안)

- 회귀 실행을 13회 이상 반복해도 승인된 AC의 E3 판정이 유지됨
- 고정 이후 테스트 약화 시 E3 무효(기존 규칙 유지)
- 고정 기록 조작(build.json 직접 편집) 감지
- 전체 회귀 FAIL 0·SKIP 0, E3 기준 비완화

## 5. 범위 밖

- 이번 변경 패키지(P1–P5)에는 넣지 않습니다.
- 실제 제품 저장소의 기존 E2 조정 기록은 이 과제와 별개로 사용자가 판단합니다.
