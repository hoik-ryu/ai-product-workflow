# 디자인 방향 (Design Direction): {project_name}

승인된 UX 설계를 바꾸지 않고, 그 위에 어떤 모습으로 렌더링할지 정합니다. 여기서 승인된 시각 결정(VD)만 정식 렌더링(프리뷰)에 씁니다.
화면·정보·행동·토큰 이름을 바꿔야 하면 이 문서에서 결정하지 않고 7장 변경 요청(①·②)으로 남겨 UX 설계를 다시 엽니다.

- **브랜드·시각 방향**: <한두 문장, 참고 자료 링크>

- **규칙 출처**: <이름@버전, 또는 '없음'>

## 4. 정책 값

프로젝트가 정한 값입니다. 엔진 기본값은 없습니다. 해당 없으면 '해당 없음(사유)'.

| 정책 | 값 | 근거 |
|---|---|---|
| density | <예: 첫 화면 목록 8행 이상> | |
| touch.min | <예: 44px, 보이는 크기와 누름 영역 구분> | |
| safe_area | <예: 하단 34px 가정> | |

## 5. 렌더링 경로

- **렌더러**: code | figma | both
- **최종 시각 승인**: `design-preview/` 트리 해시 + 06 문서(Figma는 검토용 렌더)

| 화면 | 상태 | 적용 VD |
|---|---|---|
| SCR-001 | SCR-001-ST1, SCR-001-ST3 | VD-001 |

## 7. UX Spec과의 차이와 변경 요청

변경 요청은 `impact --design`으로 분류해 적습니다. ①·②(UX Spec)가 '기각'이 아닌 상태로 남아 있거나, conditional·needs_review가 '미결'이면 제출할 수 없습니다.
