# UX 설계 문서 규칙과 추적성

## 생성 순서

1. `01-information-architecture.md`: 역할·셸·플랫폼, 사이트맵, **라우트 표**, 접근 매트릭스
2. `02-screens.md` 화면 목록 + 화면별 **최소 필드**(목적·역할·플랫폼·경로·추적)
3. `trace --stage structure` → 사용자에게 IA와 화면 목록을 제시하고 **"구조 확인"**을 받음 → `checkpoint`
4. `03-screen-flows.md`: FLOW별 화면 전이와 **FLOW 단계 → 화면 대응표**(대안·오류 경로 포함)
5. `02-screens.md` 상세 명세: 레이아웃, 정보 우선순위·권한별 노출, 행동, 입력, **상태 6종**, 컴포넌트
6. `04-ui-system.md`: 02에서 반복된 패턴만 컴포넌트로, 최소 토큰
7. `05-design-traceability.md`: US→화면, AC→화면·상태/비UI, 커버리지, 체크리스트 결과, 기획 피드백
8. `trace --stage ux_spec` 통과 → `review-checklist.md` 자체 점검 → `submit` → **"UX 설계 승인"** 요청

각 파일을 쓴 뒤 `done --path <파일>`을 실행합니다. 모든 파일의 front matter `revision`은 준비 중인 revision(현재 revision + 1)입니다.

## ID

| 접두사 | 의미 | 정의 위치 |
|---|---|---|
| `UXD-` | UX 결정 | 00 |
| `DQ-` | 미결 디자인 질문 | 00 |
| `PF-` | 기획 재검토 대상(기획 피드백) | 00 |
| `SCR-` | 화면 (`## SCR-001: 이름`) | 02 |
| `SCR-###-ST#` | 화면 상태 | 02의 상태 표 |
| `CMP-` | 컴포넌트 (`### CMP-001: 이름`) | 04 |
| `FB-` | 프리뷰 피드백 | 06 |

번호는 재사용하지 않습니다. 폐기한 항목은 헤딩을 `~~SCR-007~~ (rN에서 폐기: 사유)`로 남깁니다(스크립트는 폐기 헤딩을 무시).
기획 ID(US/AC/FLOW/FR/NFR, PRD의 확정 사항 `C-xx`)는 디자인 문서에서 참조만 하고 새로 만들지 않습니다. 확정 사항은 PRD "사용자가 확인한 사항" 표의 첫 열(`| C-01 | ... |`)에서 읽으며, 바뀌면 `impact`가 이를 참조하는 UXD·화면을 찾습니다.

## 스크립트가 검사하는 것(`trace`)

| 범위 | 오류(제출 거부) | 경고 |
|---|---|---|
| ux_planning | UXD 없음, UXD 상태 값, 관련 ID 없음, 기획에 없는 ID | 미결 DQ, 미해결 PF |
| structure | 01 라우트 표와 02 화면 불일치, 플랫폼 값, 기획에 없는 ID, **화면 없는 Must US** | 추적 ID 없는 화면 |
| ux_spec | 위 + 상태 표 6종 누락, 정의 안 된 CMP/UXD 참조, 없는 SCR/상태 참조, **대응 없는 FLOW 단계**, US(Must/Should) 행 누락, Must US 화면 없음, Should US 화면·후속 없음, **AC 행 누락**, 화면도 `비UI: 사유`도 없는 AC | 쓰이지 않는 CMP, 화면에 반영 표시 없는 UXD, US 없는 화면 |

스크립트는 ID와 구조만 봅니다. **UX가 적절한지는 `review-checklist.md`와 사용자 승인으로 판단합니다.**

## 기획과의 경계

- 기획 문서(02–05)를 수정하지 않습니다.
- 설계 중 기획 공백·모순을 발견하면 00의 `PF`와 05의 "기획 피드백"에 기록하고, 진행을 막는 경우 `/product-start` 재검토를 안내합니다.
- 기획 범위 밖 화면을 추가하지 않습니다. 공통 화면(404, 권한 없음 등)은 추적란에 근거 AC나 사유를 적습니다.
