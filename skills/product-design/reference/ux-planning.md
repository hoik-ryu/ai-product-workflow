# UX Planning 인터뷰 가이드

목표: 질문을 많이 하는 것이 아니라, **화면 설계에 영향을 주는 미결정 사항을 충분히 해소**하는 것입니다.

## 1. 분석(질문 전, 파일에 결과를 남김)

승인된 02–05를 읽고 `.ai-workflow/design-notes.md`의 `## 분석`에 다음을 적습니다.

1. **이미 확정된 사항**(다시 묻지 않음): FR·NFR 본문, 확정 사항(C-xx), AC의 Given/When/Then, FLOW 단계·대안 경로, 범위 제외 항목. 예: "예약 단위 기본 30분, 예약 확정 후 변경 불가(C-06)".
2. **주제 목록**: 기능(대개 FLOW 단위)별로 묶고 우선순위를 정합니다.
   - 우선순위: (1) 핵심 FLOW·Must US가 많은 기능 → (2) 권한·데이터 노출 규칙이 걸린 기능 → (3) 나머지 Must → (4) Should
3. **주제별 미결정 UX 항목**: 아래 관점에서 기획에 답이 없는 것만 고릅니다.

| 관점 | 예시 질문 |
|---|---|
| 정보 우선순위 | 첫 화면에서 가장 먼저 보여야 할 정보는? 무엇을 접어 둘까? |
| 사용자 행동 | 주요 행동은 한 번에? 단계별? 되돌리기가 필요한가? |
| 입력·출력 | 입력 방식(선택/직접 입력), 기본값, 결과 표시 형태 |
| 권한 | 역할별로 같은 화면에서 무엇이 달라지나? |
| 상태 | 빈 상태·로딩·실패 때 무엇을 안내하나? |
| 예외 처리 | 충돌·중복·취소·네트워크 오류 시 사용자 경험 |
| 모바일 UX | 한 손 조작, 화면 폭에서 정보 밀도, 현장 사용 환경 |

## 2. 라운드 진행

- **한 라운드 = 한 주제, 질문 2–4개.** 번호를 붙이고 짧게 답할 수 있게 선택지를 줍니다.
- 질문마다 **권장안과 근거**를 붙입니다(기획 ID 근거 포함). 예: "권장: b) 예약 카드 2열 — FLOW-004-S3에서 운영자가 당일 예약을 한눈에 비교해야 하므로".
- 관련 기획 ID를 질문에 함께 적습니다(US/AC/FLOW/FR/NFR, 확정 사항 `C-xx`).
- 이미 확정된 사항은 묻지 않습니다. 확인이 필요하면 "기획에 따르면 X입니다(FR-0xx). 이 화면에서는 이렇게 보여 주려 합니다"라고 **설명**만 합니다.
- **질문을 제시하기 전에** 라운드를 `design-notes.md`에 아래 형식(상태 `답변 대기`)으로 먼저 저장하고 `pending`으로 형식을 확인합니다. 그다음 저장한 내용 그대로 제시하고 멈춥니다.

```markdown
## 라운드 3 — 예약 현황
- **상태**: 답변 대기
### 질문
#### R03-Q1: 예약 시간 변경 조작
- **선택지**: a) 탭-탭 / b) 드래그 / c) 하단 시트에서 선택
- **권장안**: c) — 한 손 조작, 드래그 오조작 방지
- **관련**: US-021, AC-035, FLOW-004-S4
### 답변 원문
(대기 중)
```

  - 질문 ID는 `R<라운드 두 자리>-Q<번호>`입니다. 라운드당 질문은 1–4개(보통 2–4개, 확인 질문은 1개도 가능)입니다.
  - `선택지`, `권장안`, `관련`(기획에 있는 ID)은 필수입니다. 답변 대기 라운드는 한 번에 1개만 둡니다.
  - 상태 값: `답변 대기` | `답변 완료` | `취소`(사유). 답을 기록하면 `답변 완료`로 바꾸고 `### 답변 원문`에 사용자 답을 그대로 적습니다.
- **재개할 때** `check`의 `pending_round`(또는 `pending`)에 대기 라운드가 있으면, **기록된 질문을 그대로** 다시 보여 줍니다. 질문을 새로 만들거나 선택지를 바꾸지 않습니다. 질문을 바꿔야 하면 기존 라운드를 `취소(사유)`로 바꾸고 새 라운드를 저장한 뒤 제시합니다.
- 답변 대기 라운드가 남아 있으면 `submit --stage ux_planning`이 거부됩니다.
- 주제당 보통 1–2라운드면 충분합니다. 화면 설계에 영향이 없는 세부(문구, 색상 취향)는 묻지 않고 권장안으로 기록합니다.
- 사용자가 "나머지는 권장안으로"라고 하면 남은 항목을 `권장안 수용`으로 기록하고 요약해 보여 줍니다.

## 3. 답변 처리

답을 받으면 **즉시** 해당 라운드의 상태를 `답변 완료`로 바꾸고 `### 답변 원문`에 사용자 답을 그대로 적은 뒤, `00-ux-decisions.md`를 갱신하고 `done --path docs/design/00-ux-decisions.md`를 실행합니다.

| 사용자 응답 | 기록 |
|---|---|
| 분명한 답 | `UXD` 상태 `확정` |
| "알아서" / 권장안 선택 | `UXD` 상태 `권장안 수용`(근거 포함) |
| "모르겠다" / 건너뜀 | `DQ` 미결(권장 기본값 포함). 화면 설계 전 다시 확인하거나 권장값으로 진행할지 묻기 |
| 모호한 답(예: "적당히 크게") | 기록하지 않고 **확인 질문**: 구체적 선택지 2–3개로 다시 묻기 |
| 기획 범위를 바꾸는 답(새 기능, 범위 제외 항목 포함, FR 변경) | 결정하지 않음. `PF`로 기록하고 "기획 재검토 대상"이라고 알림. 현재 기획 범위 안의 대안을 권장 |

- 관련 ID는 `00` 문서의 `**관련**` 줄에 기획 ID만 적습니다(스크립트가 존재 여부를 검사).
- 후속 질문은 직전 답에서 생긴 새 미결 사항만 만듭니다(예: "목록형"을 고르면 정렬 기준을 묻기).

## 4. 결정 변경

- 이전 결정을 바꾸면 기존 UXD를 지우지 않고 헤딩을 `~~UXD-003~~ (rN에서 UXD-012로 대체)`로 바꾸고 새 UXD를 만듭니다.
- `refs --id UXD-003`으로 이 결정을 참조하는 화면·컴포넌트를 찾아 영향을 보고합니다.
- 이미 UX 설계나 프리뷰가 승인된 뒤라면 `reopen --stage ux_planning`이 필요하고, 그러면 UX 설계·프리뷰 승인이 무효화된다는 점을 먼저 알리고 확인을 받습니다.

## 5. 완료

- 모든 주제가 완료이거나 남은 항목이 DQ·PF로 정리되면 요약합니다: 주제별 UXD, 미결 DQ, PF.
- `trace --stage ux_planning` → `submit --stage ux_planning` → "UX 결정 확정"(또는 "승인")을 요청합니다.
- 미결 DQ가 있으면 "권장 기본값으로 설계에 반영하고 DQ로 남긴다"는 점을 분명히 말합니다.
