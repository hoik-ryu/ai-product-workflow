# UX 설계 검토 체크리스트

`submit --stage ux_spec` 전에 자체 점검하고 결과를 `05-design-traceability.md` 4장에 적습니다. 사용자에게 승인을 요청할 때 요약해서 보여 줍니다.
스크립트가 판단하지 않는 항목입니다. "통과 / 이슈(설명) / 해당 없음"으로 적습니다.

## 1. 흐름과 구조

- [ ] 핵심 FLOW를 가장 적은 화면 이동으로 끝낼 수 있는가
- [ ] 역할별 진입점이 분명하고, 권한 없는 화면으로 가는 링크가 노출되지 않는가
- [ ] 모든 화면에서 "지금 어디이고 다음에 무엇을 하는지" 알 수 있는가(제목, 주요 행동 1개)
- [ ] 되돌릴 수 없는 행동(삭제, 확정, 역할 변경)에 확인 단계가 있는가

## 2. 정보와 권한

- [ ] 화면마다 정보 우선순위가 정해져 있는가(첫 화면에서 보여야 할 것)
- [ ] 권한별 노출 규칙이 기획(NFR, AC)과 일치하는가(예: 회원에게 다른 회원 연락처 비노출)
- [ ] 개인정보를 필요 이상으로 보여 주지 않는가

## 3. 상태와 예외

- [ ] 기본·로딩·빈 상태·오류·권한 없음·충돌 중 해당하는 상태의 안내 문구와 다음 행동이 있는가
- [ ] 동시 수정·충돌, 네트워크 실패, 중복 제출 상황이 정의되어 있는가
- [ ] 오류 메시지가 원인과 해결 방법을 말하는가

## 4. 모바일 UX

- [ ] 주요 행동이 한 손으로 닿는 위치에 있는가
- [ ] 좁은 폭(360–390px)에서 표 대신 카드·목록 등으로 정보를 재배치했는가
- [ ] 현장 사용 환경(밝은 곳, 이동 중, 빠른 조작)을 고려했는가

## 5. 접근성 기본(WCAG 2.2 AA 기준에서 설계 단계에 확인할 항목)

- [ ] 텍스트 대비 4.5:1 이상, 큰 텍스트·아이콘·경계선 3:1 이상(1.4.3, 1.4.11)
- [ ] 색만으로 정보를 구분하지 않는가(팀, 상태, 오류에 글자·아이콘 병행)(1.4.1)
- [ ] 터치·클릭 영역 최소 24×24px, 주요 버튼은 44px 이상 권장(2.5.8)
- [ ] 모든 입력에 보이는 레이블이 있고, 오류를 텍스트로 알리는가(3.3.1, 3.3.2)
- [ ] 키보드 포커스 순서와 포커스 표시가 정의되어 있는가(2.4.3, 2.4.7)
- [ ] 애니메이션은 일시정지·건너뛰기가 가능하고, 움직임 줄이기 설정을 존중하는가(2.2.2, 2.3.3)
- [ ] 200% 확대에서도 내용이 잘리지 않는가(1.4.4, 1.4.10)

참고: W3C Web Content Accessibility Guidelines (WCAG) 2.2, https://www.w3.org/TR/WCAG22/
