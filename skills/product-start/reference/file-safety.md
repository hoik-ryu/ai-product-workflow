# 파일 안전: 덮어쓰기, Git, 백업

Git이 기본 변경 이력 수단입니다. 백업은 Git이 내용을 보호하지 못할 때만 쓰는 대비책입니다.

## Skill이 관리하는 파일(확인 불필요)

- `.ai-workflow/state.yaml`
- `.ai-workflow/discovery-notes.md` (덧붙이기만 함)

그 밖의 파일은 모두 **사용자에게 보이는 산출물**이며 아래 규칙을 따릅니다.

## 새 파일 만들기

경로가 아직 존재하지 않고, 현재 단계에서 허용되는 경우(`state-machine.md` 참조)에만 확인 없이 만들 수 있습니다. 쓰기 직전에 존재 여부를 다시 확인합니다.

## 기존 산출물 수정 또는 덮어쓰기

1. 먼저 변경 내용을 설명합니다. 어떤 파일인지, 어떤 섹션·ID를 추가·변경·폐기하는지, 그 이유는 무엇인지 설명합니다.
2. 확인을 요청합니다. 사용자가 확인할 때까지 아무것도 쓰지 않습니다.
3. 백업이 필요한지 판단합니다.

```bash
git -C <project> rev-parse --is-inside-work-tree        # Git 저장소인가?
git -C <project> ls-files --error-unmatch <file>        # 추적 중인 파일인가?
git -C <project> status --porcelain -- <file>           # 커밋되지 않은 변경이 있는가?
```

| 상황 | 조치 |
|---|---|
| Git 저장소, 추적 중인 파일, 커밋되지 않은 변경 없음 | 백업하지 않음. 이전 버전은 Git에 있음 |
| Git 저장소가 아님 | 백업 |
| 추적되지 않는 파일 | 백업 |
| 커밋되지 않은 변경이 있는 파일 | 백업 |

4. 백업 절차(파일당 한 칸, 누적하지 않음):
   - 경로: `.ai-workflow/backup/<filename>` (예: `.ai-workflow/backup/02-prd.md`)
   - 같은 파일의 이전 백업을 덮어씁니다. 번호 붙은 사본을 만들지 않습니다.
   - 기존 백업이 현재 파일과 바이트 단위로 같으면 복사를 건너뜁니다.
   - 백업 경로를 사용자에게 알립니다.
5. 파일을 쓰고 `state.yaml`을 갱신합니다.

## 금지

- 산출물을 삭제하지 않습니다.
- `git commit`, `git push`, `git checkout`, `git reset`, `git stash`를 실행하지 않습니다. 필요하면 명령을 사용자에게 제안합니다.
- 이번 세션에서 내용을 읽지 않은 파일을 덮어쓰지 않습니다.
