# Discovery 인터뷰 가이드

목표: 사실을 지어내지 않고 모호한 아이디어를 Discovery 문서로 만듭니다.

## 필수 주제(초안 작성 전에 답을 받거나, 가정 또는 미결로 남겨야 함)

1. **문제**: 어떤 불편이, 누구에게, 얼마나 자주 생기는가
2. **대상 사용자**: 주요 사용자 그룹과 그들의 상황
3. **핵심 시나리오**: 사용자가 하는 가장 중요한 한 가지 일
4. **MVP 범위**: 첫 버전에 반드시 들어갈 것과 명시적으로 뺄 것

## 선택 주제(관련 있거나 쉽게 물을 수 있을 때만)

현재 대안, 성공 지표, 제약(플랫폼, 예산, 일정, 규제), 수익 모델, 리스크

## 질문 방법

- 먼저 아이디어를 1–2문장으로 다시 정리하고, 입력에서 이미 분명한 내용을 나열합니다. 사용자가 이미 말한 것은 묻지 않습니다.
- 라운드마다 영향이 큰 순서로 3–5개 질문합니다. 사용자가 짧게 답할 수 있게 번호를 붙입니다("1. ... 2. ...").
- 가능하면 구체적인 선택지를 제시합니다(예: "a) 개인 학습자 b) 동호회 코치 c) 기타").
- "모르겠다", "알아서 해줘", 질문 건너뛰기를 허용합니다.
- 최대 3라운드입니다. 그 뒤에는 있는 내용으로 초안을 씁니다.
- 질문은 `project.language`(기본 한국어)로 씁니다.

## 답변 기록

사용자가 답하면 즉시 해당 라운드를 `.ai-workflow/discovery-notes.md`에 원문 그대로 덧붙입니다. 아이디어는 `## 아이디어` 아래에, 이후 라운드는 `## 라운드 N` 아래에 질문과 답을 적습니다. 이 기록은 사용자가 무엇을 확인했는지에 대한 근거이며, 인터뷰가 중단돼도 이어갈 수 있게 합니다.

## 답이 없는 항목

| 사용자 응답 | 기록 방식 |
|---|---|
| 분명한 답 | 본문(사용자 확인 사항) |
| "알아서 해줘" / 위임 | 제안한 가정과 근거를 `ASM-xxx`로 기록 |
| "모르겠다" / 건너뜀 / 묻지 않음 | `Q-xxx` 미결 질문(제안 기본값을 함께 적을 수 있음) |

`ASM`이나 `Q`를 사실로 본문에 옮기지 않습니다. 사용자의 명시적 확인만 이를 해소할 수 있습니다. 해소되면 상태를 `해결 (rN): <답변>`으로 표시하고 본문을 갱신합니다.
